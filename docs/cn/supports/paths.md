# 运行时路径

_位于 `src/raser/supports/paths.py` 的 RASER 5.0 路径与上下文契约_

---

## 📋 职责

Paths 为所有调用者统一解释工作根目录、当前项目、组件根目录、打包应用资产与逻辑命名空间。它根据明确的路径输入计算位置。组件模式、科学模型与工作流结果归属相应调用者。

## 🗂️ 运行时根目录

| 变量 | 输入含义 | 默认含义 |
| --- | --- | --- |
| `RASER_WORK_PATH` | 命名项目的父目录 | 仓库工作目录 |
| `RASER_PROJECT_PATH` | 此次调用的当前项目 | 当前目录 |
| `RASER_COMPONENT_PATH` | 额外的有序组件根目录 | 空根目录列表 |

路径工具返回 `Path` 值。文件系统修改交给 [Output](output.md) 或明确持有相应内容的调用者。

## 🔍 项目推断

| 选择器 | 当前项目 |
| --- | --- |
| 已有 `RASER_PROJECT_PATH` | 明确的环境值 |
| 裸项目名或探测器名 | `<work-root>/<name>` |
| `components/` 下的路径 | `components/` 上方目录 |
| 明确的路由选择文件 | 其父目录，或其 `components/` 路径段上方目录 |
| 缺少项目选择器 | 当前项目上下文 |

每条路由最多声明一个上下文选择器。`--config` 等辅助输入维持该路由选定的探测器或目标。明确上下文优先于推断。

CLI 在创建上下文派生参数前激活上下文，并在分发后恢复先前值，异常路径采用相同方式。嵌套上下文恢复紧邻的前一状态。

## 📦 组件查找

符号组件条目采用以下顺序：

1. `<project>/components/`
2. 为命令选择的应用组件根目录
3. `RASER_COMPONENT_PATH` 中的根目录
4. `src/raser/components/` 下的打包定义

根目录去重保留首次出现项。首个已存在候选项生效。必需的符号输入或明确输入在缺失时抛出 `FileNotFoundError`，其中包含请求的标识与尝试的位置。缺失具有已定义含义时，可选查找返回 `None`。

打包应用配置根据应用与相对资产名解析，其命名空间与可复用[组件](../components/README.md)查找相互独立。

## 🔗 依赖方向

环境设置建立默认根目录。[CLI 路由](../cli/raser.md)激活一个临时上下文。Applications 与 Core 随后通过明确的 Supports 接口请求路径。

## ⚠️ 失败契约

缺少必需输入、父目录逃逸或无效逻辑路径段、未知应用资产及文件系统解析错误均保持可见。上下文清理在重新抛出分发错误前恢复先前环境值。
